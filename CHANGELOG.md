## [1.5.0] - 2026-10-23
### Added
- Суточная ротация логов: папка logs/, один файл на сутки (bot.log,
  thermal_guard.log), автоматическое удаление файлов старше 30 дней;
  служебные строки скриптов запуска пишутся в logs/service.log
- Журналирование всех операций кэша разрешённых с указанием причины
  ([cache+] / [cache-]) — происхождение любой записи теперь расследуемо
- Выверка кэша разрешённых по составу группы: при старте бота,
  по команде /refresh и планово раз в сутки в фоновом режиме
- Троттлинг автопроверок обновлений GitHub (не чаще раза в 30 минут)
  и понятная диагностика 403 rate limit с временем сброса лимита
  - Расписание питания и статуса меню (только Ubuntu-сервер): сон в будни 23:00–08:00,
  полное выключение Пт 23:00 – Пн 08:00; главное меню у пользователей редактируется
  на «рабочий день закончился» / «отключён на выходные» и восстанавливается при включении
- Самовосстановление режима: машина, включённая вне расписания, сама возвращается
  в сон/выключение через 2 минуты
- systemd-автозапуск бота без входа пользователя, wake-таймер пробуждения в будни,
  резервное выключение в пятницу 23:15, best-effort RTC-будильник на понедельник

### Security
- Закрыта уязвимость повышения прав: события chat_member обрабатываются
  ТОЛЬКО из боевой группы (GROUP_CHAT_ID). Ранее любой, добавивший бота
  в свой чат, мог выдать доступ к боту произвольным людям; события из
  чужих чатов теперь игнорируются и логируются как предупреждение

### Fixed
- Уведомление о возврате температуры к норме не отправлялось, если
  термозащита перезапускалась между WARN и NORM: состояние WARNED
  теперь восстанавливается из статус-файла
- Уведомления термозащиты терялись при сетевых таймаутах и ошибках Telegram:
  добавлены повторы (до 3 попыток) и точное описание ошибок в логе
- Ошибка 403 (rate limit) при проверке обновлений после частых перезапусков:
  автопроверки троттлятся, состояние последней проверки хранится в файле

### Changed
- Команда /update проверяет GitHub принудительно, в обход троттлинга

## [1.4.0] - 2026-10-22
### Added
- Независимый сервис термозащиты сервера (thermal_guard): мониторинг температур
  CPU/GPU/NVMe, уведомления админам, аварийное выключение при критическом перегреве
- Экран «Параметры сервера» в админ-панели с температурами и нагрузкой
- Установка термозащиты на Ubuntu одной командой (server/install_server.sh)

### Fixed
- Бот больше не падает при старте, если bot_log.txt недоступен для записи:
  логирование переключается на резервный файл или консоль

## [1.3.1] - 2026-10-21
### Fixed
- Конфликт «terminated by other getUpdates request»: бот больше не может запуститься
  во второй копии на одной машине (mutex ОС), а при конфликте с копией на другой машине
  пишет понятный диагноз и корректно ждёт
- Flood control на SetMyCommands при частых перезапусках: команды устанавливаются
  только при фактическом изменении их набора
- UnicodeEncodeError ('charmap' codec) при выводе эмодзи в скрытом режиме запуска —
  потоки вывода принудительно переведены в UTF-8

### Changed
- start_bot.bat останавливает цикл автоперезапуска, если обнаружена другая копия бота
  (код выхода 42), вместо бесконечных перезапусков каждые 5 секунд


## [1.3.0] - 2026-10-20
### Added
- Автоматическая проверка обновлений с GitHub: при запуске бота и раз в сутки
- Команда /update — проверка и установка обновления с кнопкой подтверждения
- Команда /changelog — список изменений текущей установленной версии
- Уведомления админам о новой версии со списком изменений
- Режим AUTO_UPDATE (выключен по умолчанию) для полностью автоматической установки
- Файлы VERSION и CHANGELOG.md для версионирования


### Fixed
- Выбор прошедшего времени при админской записи
- Время окончания больше не может быть раньше начала при админской записи
- Ошибка «файл занят другим процессом» при повторном запуске бота
- Ошибка создания задачи автозапуска в Планировщике заданий
- Отказ в допуске участникам группы со статусом restricted

### Changed
- Ежемесячные отчёты по статистике (1-е число, 13:00)
- install_all.bat стал самодостаточным: сам создаёт все скрипты запуска и автозапуск
